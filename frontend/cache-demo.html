Demo: midiendo el impacto real del caché

Desempeño en APIs REST · Caché — Sesión 8

Esta demo guarda en un caché en memoria (un Map del navegador) el resultado de una petición costosa. La primera vez se consulta el origen (MISS) y las siguientes se sirven desde el caché (HIT) hasta que expire el TTL o se invalide. La petición al servidor está simulada para reproducir el ejemplo de la clase.

peticionConCache() — patrón Cache-Aside 

async function peticionConCache(endpoint, ttl) {
  const entrada = cache.get(endpoint);
  if (entrada && entrada.expiresAt > ahora) {
    return { ...entrada.value, status: 'HIT' };
  }
  const resultado = await peticionReal(endpoint);
  cache.set(endpoint, {
    value: resultado,
    expiresAt: ahora + ttl * 1000,
  });
  return { ...resultado, status: 'MISS' };
}

Actividad práctica

  1. Haz 3 peticiones al mismo endpoint: observa el primer MISS y los siguientes HIT.
  2. Compara los tiempos promedio en las tarjetas: MISS vs. HIT.
  3. Cambia el TTL a 2 segundos, espera y vuelve a pedir: ¿cuándo vuelve a ser MISS?
  4. Usa "Invalidar caché" y observa que la próxima petición es MISS otra vez.
  5. Prueba los tres endpoints y compara cómo cambia el impacto según la latencia original.
  6. Discute con tu compañero: ¿qué TTL usarían para un catálogo? ¿Y para un carrito de compras?
